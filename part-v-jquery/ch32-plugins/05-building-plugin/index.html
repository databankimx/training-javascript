Training guide

This section contains the short training guide.

Good training material gives each idea enough room to breathe. A reader should be able to follow the example, change one detail, and still understand why the result changed. That is more useful than a page that merely demonstrates how quickly a widget can be initialized.

As you move through the guide, notice the relationship between the visible link and its destination. The link text explains the destination in human terms, while the fragment identifies the section in the document.

There is no hidden server route behind this example. Everything is already in the page, which means the plugin can improve the presentation without fetching another document.

Reference page

This section contains the reference material.

Reference pages tend to be denser than lessons. They collect option names, defaults, callback signatures, and lifecycle methods in one place. A good navigation aid helps the reader understand where a link will take them before they click.

Imagine this section continued for several screens. The plugin's small annotation would still be useful because the target remains visible beside the link, even when the actual destination is far below the current viewport.

When you build a plugin for a real application, start with that user need. The code should serve the design, not the other way around. Otherwise we are just adding another method to `$.fn` because we had a quiet afternoon.
